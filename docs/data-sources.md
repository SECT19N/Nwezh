# Data sources

Decisions on where Nwezh's data, text and assets come from. Licenses were checked from public pages
on 2026-10-28 and are not legal advice. Anything marked **verify** must be confirmed with the rights
holder before release.

Nwezh is permanently free: no ads, no paid tier, no account, no analytics.

## Quran text (Arabic)

- **Source:** [Tanzil](https://tanzil.net), Uthmani text.
- **License:** CC BY 3.0. The text must not be modified. We must credit Tanzil Project and link to
  tanzil.net, and keep its copyright notice in verbatim copies.
- **Handling:** store the text unaltered. Any processing (splitting into verses, indexing) must not
  change the characters. Add a licenses screen with the attribution.

## Quran font

- **Default:** Amiri Quran (SIL OFL 1.1). Clear license, designed for Quran typesetting.
- **Not used for now:** KFGQPC Uthmanic Hafs. Its license is unclear and sources conflict. Use only
  with written permission from the King Fahd Complex.
- **Not needed:** per-page mushaf fonts, since the reader is verse-by-verse.

## Other fonts and icons

- Roboto Flex (Latin UI), Noto Naskh Arabic and Noto Sans Arabic (Arabic-script UI): SIL OFL.
  Bundled locally so the app works offline.
- Scheherazade New (SIL OFL): candidate for Sorani UI text, still to be tested.
- Material Symbols Rounded: Apache-2.0. Bundle only the glyphs used.

## Theme

Fixed palette (plum/mauve primary, light and dark). No dynamic color.

## Cities

- **Source:** [GeoNames](https://www.geonames.org) (CC BY 4.0), processed at build time into a
  compact offline file with search.
- **Names per language:** use GeoNames alternate names where they exist (English, Kurdish, Arabic).
  Fall back to English where a language has no name.
- **Overrides:** a small hand-reviewed file for Kurdistan Region cities, so the spellings shown are
  the approved ones.
- **Time zones:** IANA zone id per city.

## Calculation and Hijri

- Prayer times, Qibla and fasting rules are implemented in our own library modules, tested against
  published timetables.
- Hijri calendar: implemented in our own `hijri` module, not through platform calendars. Umm al-Qura
  is a calendar definition, not a library. See "Hijri implementation" below.

## Hijri implementation

Umm al-Qura is Saudi Arabia's official calendar. Its month starts come from a published rule (based
on the moon's position at sunset in Makkah) and are published as a table, so the module needs that
data, not a dependency. Plan:

- A compact table of month lengths (29 or 30 days) per Hijri year, generated by a build-time script,
  with a known anchor date to convert to and from Gregorian dates.
- A tabular civil-calendar fallback outside the table's range.
- User adjustment of -1, 0 or +1 day, with per-month confirmation for Ramadan, Shawwal and Dhu
  al-Hijjah.
- **Table source (decided):** the Umm al-Qura month-length table in ICU's `islamcal.cpp`
  (`UMALQURA_MONTHLENGTH`), covering 1300-1600 AH. Each year is a 12-bit value, one bit per month,
  where 1 means a 30-day month and 0 means 29 days. ICU is under the Unicode license, so we keep the
  notice and credit ICU in the licenses screen. **Verify** the license text before release.
- **Cross-checks:** R.H. van Gent's Umm al-Qura conversion tables (Utrecht University) for 1420-1434
  AH, and Ramadan and Eid dates announced for 2025-2030. Sources are known to differ on a few dates,
  so each mismatch is recorded in the tests rather than silently fixed.
- **Caveat:** we only cross-check from 1420 AH (1999 CE) onward. Earlier years may not match what
  was officially announced at the time, because the rules used then differed. This does not matter
  for current use, which only looks at today and future dates.
- The generator script lives in the repo and reproduces the table from the ICU source, so updating
  it is repeatable.

## Adhan audio

Pinned. Not decided for v0.5. The app can ship with a chime and notification-only mode.

## Libraries policy

Domain logic is built in-house as separate, dependency-light modules with clean public APIs, so they
can be extracted and published later:

- prayer times
- Qibla
- Hijri calendar
- fasting rules
- Quran data model and loader
- city database

Infrastructure (persistence, navigation, DI, serialization, date/time) uses standard libraries.
